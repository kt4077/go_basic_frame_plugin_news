# 新闻资讯插件数据库说明 v0.1.0

## 迁移

迁移文件：`database/migrations/0.1.0.sql`。升级前必须备份数据库，迁移由插件安装器在事务与插件操作锁保护下执行。

`plg_news_article` 新增唯一业务键 `uid` 以及 `like_count`、`share_count`、`comment_count`。历史文章的 `uid` 在插件启动时使用 `pkg/sn.Generate()` 分批补齐；完成补齐前字段保持可空以兼容在线升级。

## 新增表

| 表名 | 用途 | 主要唯一约束 |
| --- | --- | --- |
| `plg_news_article_like` | 文章点赞状态 | `uid`；`article_uid + member_sn` |
| `plg_news_comment` | 一级评论与回复 | `uid`；`member_sn + request_uid` |
| `plg_news_comment_image` | 评论图片相对路径 | `uid` |
| `plg_news_comment_like` | 评论点赞状态 | `uid`；`comment_uid + member_sn` |
| `plg_news_share_record` | 分享发起记录 | `uid`；`member_sn + request_uid` |

所有表均为 InnoDB、`utf8mb4_general_ci` 并包含表注释和字段注释。`id` 仅作为内部聚簇主键；跨表业务关联使用唯一 `uid`，会员关联使用 `sys_member.sn`。当前不建立物理外键，删除与状态变更由事务控制。

评论状态：`1` 待审核、`2` 显示、`3` 关闭。点赞状态：`1` 点赞、`2` 取消。所有枚举从 1 开始。

## 核心表引用与卸载

插件逻辑引用 `sys_member.sn` 获取用户公开资料，但不写会员表，也不设置物理外键。Remove 保留所有 `plg_news_*` 数据；Purge 会删除插件业务表，因此执行前必须备份。评论图片文件及 `sys_upload_file` 记录不会自动删除，避免误删共享文件。

## 外部数据库引用

| 检查项 | 结论 |
| --- | --- |
| 是否引用核心业务表 | 是，逻辑读取 `sys_member.sn`、昵称与头像，不建立物理外键且不写会员表 |
| 是否引用其他插件表 | 否 |
| 是否允许 Purge | 是，但必须先停用插件、确认无外部引用并完成备份 |
| 是否自动删除文件 | 否，评论图片和文章封面可能被共享，必须人工审查 |

Remove 只移除插件代码、菜单和安装状态，保留全部业务表与互动数据。Purge 会彻底删除 `plg_news_*` 插件业务表、迁移记录与归档文档，属于不可恢复操作。
