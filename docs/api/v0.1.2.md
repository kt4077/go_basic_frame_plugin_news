# 新闻插件 API v0.1.2

## 版本说明

本版本新增的是管理端资讯复用交互，不新增、不删除也不修改后端接口。复用页面读取原资讯详情后，使用新的文章标识调用现有保存接口创建独立资讯。

## 管理端复用流程

1. `GET /admin/plugin/news/article/detail?id={id}` 读取选中资讯；
2. 管理端清除数据库主键，生成约 11 位的可编辑短文章标识，并清零统计信息；
3. `POST /admin/plugin/news/article/save` 提交新资讯，其中 `id=0`；
4. 服务端沿用新增校验、权限校验和唯一标识约束，不修改原资讯。

上述接口均由管理端鉴权与菜单权限中间件保护。复用操作复用“文章详情”和“保存文章”权限，不增加重复权限节点。

### 字段处理规则

| 字段 | 复用行为 |
| --- | --- |
| `id`、`uid` | 不复用；提交 `id=0`，新 UID 由服务端新增逻辑生成 |
| `slug` | 重新生成 `n + 6 位时间片 + 4 位随机值` 的短标识，保存前允许修改 |
| `title` | 复用原值并追加“（复用）”，提醒编辑人员确认标题 |
| 分类、摘要、作者、来源、封面、正文、启用状态、排序 | 预填原资讯数据 |
| 发布状态、发布时间 | 不复用，新资讯按新增流程处理 |
| 真实阅读、虚拟阅读、点赞、收藏、分享、评论 | 不复用，全部从零开始 |

短标识总长度约 11 位，随机部分使用浏览器 `crypto.getRandomValues` 生成，并继续由服务端唯一索引做最终冲突校验。

## 兼容性

- v0.1.1 的接口路径、参数和响应保持兼容；
- 点赞、收藏、分享、评论及互动状态接口保持不变；
- 用户端接口不返回管理端复用状态或其他冗余字段。
